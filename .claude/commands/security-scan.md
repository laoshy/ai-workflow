# 安全专项复查

## 复查范围

$ARGUMENTS （为空时：审查当前未提交改动中的安全敏感部分）

## 触发判断

改动涉及以下任一项时必须执行本命令，否则提示用户可跳过：
认证/鉴权、API 接口、数据库/文件 IO、网络请求、用户输入处理、密钥/配置、支付。

## 流程

1. 收集安全敏感的改动（git diff 过滤相关文件）
2. 派发 **security-reviewer** 子 agent，交由其按检查清单审查
3. 向用户转述发现，按风险分级：
   - 🔴 高危：注入、密钥泄漏、未鉴权访问 → 立即修复
   - 🟡 中危：缺输入校验、错误信息泄露 → 征求用户意见修复
   - 🟢 低危：加固建议 → 记录到 `docs/decisions.md`
4. 修复后重跑 `make check`，并在 `.harness/session-log.md` 记录安全复查结论
