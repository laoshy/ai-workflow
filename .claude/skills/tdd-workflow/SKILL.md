# TDD Workflow

对计划中的每一个功能点，严格执行以下循环，**禁止在没有失败测试的情况下写实现代码**。

## 循环（每个功能点一轮）

### 1. RED — 先写失败测试
- 根据计划的验收标准写测试，测试名描述行为（`test_cooldown_blocks_reentry_within_3_days`）
- 运行测试，**必须看到它失败**，且失败原因是"功能未实现"而非语法错误
- 失败证据记录下来（测试输出摘要）

### 2. GREEN — 最小实现
- 写**刚好让测试通过**的代码，不做多余设计
- 运行测试，全绿

### 3. 重构
- 在测试保护下消除重复、改善命名
- 每次重构后立即重跑测试，保持全绿

### 4. 覆盖率
- 一轮结束时跑覆盖率（如 `pytest --cov`），新逻辑必须被覆盖
- 覆盖不到的分支：要么补测试，要么在计划文档中说明为什么无法覆盖

## 纪律

- 测试与实现写进同一个提交/同一批改动，不拆分
- 测试失败时不许改测试来迁就实现，除非确认测试本身写错（需说明理由）
- 每个功能点完成后勾掉计划 checklist 对应项
- 全部功能点完成 → 运行 `make check` 作为最终验证证据
